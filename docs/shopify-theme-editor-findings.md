# Shopify Theme Editor Reference Findings

This document records browser observations of Shopify's theme editor so the local editor can be compared against a concrete reference. Add new observations here as the implementation work continues. Entries are chronological; later implementation and recheck sections supersede earlier parity notes when the local editor has since changed.

## Reference and method

- Observed in Chrome on 2026-10-13 at `https://admin.shopify.com/store/lucki-fit-2/themes/190060691778/editor`.
- The inspected theme is `Copy of lucki live production`, in Draft state, with its Home page selected.
- Observations came from the visible editor, accessibility tree, and screenshots. Navigation and selection panels were inspected without saving, publishing, or changing the Shopify theme.
- This is evidence from one store, theme, and account. Theme-specific sections and enabled apps vary by merchant; Shopify's editor chrome and interaction patterns are the parity reference.

## Editor frame

- A compact, fixed command bar spans the top. It has exit/navigation at the left; section, theme-settings, and app-embed modes; the draft theme name and status; the current template selector; inspector/mobile-preview controls; undo/redo; an overflow menu; and Publish/Save actions at the right.
- The working surface is split into a narrow, independently scrollable left panel and a large live storefront preview. The preview reflects the selected storefront template and uses the merchant's actual theme, products, images, navigation, and page content.
- Selecting a section opens a dedicated settings drawer between the tree and preview. The drawer has a back/title header, overflow menu, Cancel/discard, grouped controls, collapsible Custom CSS, and Remove section. A selected section is also highlighted in the preview; the preview remains visible.
- Preview interaction can be disabled with the inspector control. A separate mobile-preview toggle changes the storefront preview to a mobile viewport.
- The interface distinguishes saved draft changes from publishing. Undo and redo are global editor commands; undo is initially disabled until an edit occurs.

## Section tree and page composition

- The tree is grouped into Header, Template, and Footer. Groups have distinct insertion points, and the Template group represents the current page's main content.
- Sections have nested blocks, and blocks can contain nested blocks (for example, a content group containing text). Static blocks can appear alongside user-added blocks; some block rows are intentionally non-reorderable.
- Rows expose direct selection, drag reordering, contextual actions, remove, and hide/show. Expanded sections reveal child blocks and Add block. The same hierarchy is reflected in preview selection.
- Section and block rows can have merchant-edited labels that include content values (for example, `Text – lucki girls: drop 1`).
- Section insertion points are available before, between, and after existing sections. The add picker has Sections/Apps tabs, a search box, grouped section categories, and theme/app-provided entries.
- Observed picker entries include theme-specific Generate, Delivery Timeline, Size Chart Section, and Tee Suggestion Box; Banners (Hero, Hero: Bottom aligned, Hero: Marquee, Large logo, Layered slideshow, Slideshow: Full frame, Slideshow: Inset, Split showcase); Collections (Collection links: Spotlight/Text, Collection list: Bento/Carousel/Editorial/Grid); Forms (Contact form, Email signup); and Layout (Custom Liquid).
- A section row's overflow menu includes Ask for changes, Duplicate, Hide, and Remove. A selected existing section displays the same contextual actions.
- The editor includes search in the sections panel; the observed local tree does not yet establish whether search filters names only or content too.

## Templates and storefront preview

- The template selector is a searchable online-store template chooser, not just a page dropdown. Observed destinations: Home page; Products; Collections; Collections list; Gift card; Cart; Checkout and customer accounts; Pages; Blogs; Blog posts; Search; Password; 404 page; and Create metaobject template.
- Products, Collections, Pages, Blogs, and Blog posts expand to specific records/templates. Template selection changes the page being previewed and edited.
- Preview is an interactive, embedded storefront. The observed home page included a real hero, collection list, media-with-content section, featured products, comparison slider, contact form, newsletter, footer, and theme-specific content.
- The top controls support toggling the editor tree, theme settings, and app embeds; selecting a template; toggling the preview inspector; and mobile preview. The menu also exposes undo/redo and additional actions.

## Section settings: observed Hero

The Hero settings drawer showed controls grouped by meaning:

- Media 1 and Media 2 each support Image or Video. Video can be selected from an existing file. Images can be uploaded or selected from the store's file library.
- Mobile media includes Stack media and Show different media on mobile.
- Section link includes a dynamic-source connector, URL, and Open link in new tab.
- Layout includes Vertical/Horizontal direction; Left/Center/Right alignment; Top/Center/Bottom/Space between position; numeric/slider gap; Page/Full width; and Auto/Small/Medium/Large/Full screen/Custom height.
- Appearance includes selection among color schemes, media overlay, overlay color, Solid/Gradient overlay style, Up/Down gradient direction, and Blurred reflection (image-only).
- Padding exposes independent numeric/slider Top and Bottom controls.
- Custom CSS is collapsible.

This is an example of the range and conditionality expected from section schemas; individual sections have their own setting groups and block schemas.

## Media library: observed image picker

- Selecting an image opens a centered, wide modal over a dimmed editor; the current editor state remains visible in the background.
- The modal contains Search files, Sort, grid/list view, and filters for File size, Used in, and Product.
- Existing assets appear as selectable thumbnails with checkboxes, descriptive labels, and filenames/formats. Multiple selections are possible; Done is disabled until a selection is made. Cancel and close dismiss the picker.
- The upload surface offers Add files, a drag-and-drop target, and Generate image. The library includes mixed JPG/PNG assets and descriptive alt text when available.
- The video setting uses a file selector as well; this observed flow showed an existing MP4 label.
- The picker is used from a section setting without leaving the preview/editor frame.

## Theme settings and app embeds

- Theme settings are a separate editor mode with expandable categories: Logo and favicon; Colors; Typography; Page layout; Animations; Badges; Buttons; Cart; Drawers; Icons; Input fields; Popovers and modals; Prices; Product cards; Search; Swatches; Variant pickers; and Custom CSS. Initial inspection appeared to show Theme style disabled; a later live audit found an active Tinker style. See the newer audit below.
- Colors contains reusable color schemes that can be applied to sections. The observed theme had eight editable schemes and an Add Scheme action.
- App embeds is a separate mode with a Search app embeds field and per-app enable switches. The inspected store showed Login with Razorpay, Magic Checkout Script, Razorpay Reviews, Countdown timer, and Klaviyo Onsite Javascript, followed by a Find more apps link.

## Visual direction for local parity

- The Shopify editor is a restrained, dense utility interface: neutral near-white surfaces, thin dividers, compact icons and controls, restrained blue selection/actions, and little decorative treatment.
- The preview occupies most of the window and retains the site's own visual identity. Editor chrome does not inherit the merchant storefront palette.
- The local editor now has a neutral fixed command bar, Sections / Theme settings / App embeds tabs, a narrow sidebar that stacks the section tree above selected-section settings, and a full-width live storefront preview. Selecting a section scrolls it into view in the tree and highlights it in the preview. It has section search, drag and button-based reorder, tree insertion points, a searchable categorized add-section picker, section duplicate/hide/remove, desktop/tablet/phone preview controls, a working preview-inspector toggle, separate Save-draft and Publish actions, and a blue selected-section outline, label, floating duplicate/hide/remove actions, and before/after insertion controls in the storefront preview.
- The local editor reuses existing section content/media fields and repeatable card data. Nested rows can focus their parent section settings, and Add block appends a typed repeatable card when the section schema supports cards.

Sections whose schema supports repeatable cards show Expand and Add block even when the card list is empty. ## Storefront Password gate connection (2026-10-14)

- The owner-only Coming Soon admin screen can set, change, or disable the storefront password. Only a salted scrypt hash and version metadata are stored in the private `storefrontGateSettings` collection; password state returned to the page contains only availability and configured status. Changing or disabling the password increments the version and invalidates prior store-access cookies.
- “Enter using password” opens the full-screen “Enter password” gate and submits to a server action on the public site. Preview submits are intercepted and never call the server action. Responses use generic failure copy. Failed attempts are throttled to five per 15-minute window per keyed client-address digest, with the raw address not stored. The address comes only from the single-IP request header named by `STOREFRONT_TRUSTED_CLIENT_IP_HEADER`; the hosting proxy must overwrite that header. If the header is unset, absent, or invalid, visitors share the `unknown` bucket, so five failed attempts can block unlocks in that bucket for 15 minutes. The admin warns when its request has no valid configured address header. Successful unlocks receive a 30-day HMAC-signed, HttpOnly, SameSite=Lax cookie with Secure enabled in production. The cookie is distinct from the admin preview cookie and is checked against the current password version.
